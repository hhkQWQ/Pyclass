# 马文博的分步完成计划

**目标：先交付 B、C 能使用的数据，再完成自己的图表与报告，最后统筹全组提交。**

本计划依据《共享单车项目分工方案.pdf》中马文博的职责、协作方式与时间表编写。下面的函数拆分、补充产物和字段约定属于实施建议；分工方案没有完整显示的清洗阈值，必须在开发前记录清楚。

## 一、需要交付什么

| 类别 | 交付物 | 验收要求 |
| --- | --- | --- |
| 公共工具 | `src/utils.py` | 路径统一、中文字体可用、配色统一、保存图片为 300 DPI |
| 清洗脚本 | `src/data_cleaning.py` | 支持从项目根目录运行，自动创建输出目录，能重复生成相同结果 |
| 复现环境 | `requirements.txt` | 记录实际验证通过的依赖版本 |
| 数据接口说明 | `docs/data-dictionary.md`（实施时新增） | 字段名、类型、计算方式、空值含义和子集用途清晰 |
| 本地数据 | `clean_trips.csv`、`station_trips.csv` | 分别供全城时间分析和站点分析使用，不上传 GitHub |
| 数据质量结果 | `reports/tables/data_quality_summary.md`（建议新增） | 记录原始行数、各类异常、各步剔除数量与保留行数 |

| 分析展示 | `notebooks/01_cleaning_and_eda.ipynb` | 从头运行成功，复用脚本函数，不另写一套清洗规则 |

### 第 2 步：数据审查与清洗口径冻结（10 月 24 日）

**已核对的原始数据事实**

| 项目 | 本地检查结果 |
| --- | --- |
| 文件 | `题5_共享单车骑行_202401.csv` |
| 数据规模 | 238,834 行、13 列 |
| 时间范围 | 出发时间覆盖 2024-01-01 至 2024-01-31，部分还车时间跨入 2 月 |
| 车型 | `classic_bike`、`electric_bike` |
| 用户类型 | `member`、`casual` |
| 站点缺失 | 出发站点 ID 缺失 37,220 行，到达站点 ID 缺失 39,741 行 |
| 坐标缺失 | 到达纬度、经度各缺失 203 行 |

上述缺失计数可以重叠，不能相加作为删除行数；这些是原始数据审查结果，尚未完成清洗。

**要做的事**

1. 检查 `ride_id` 重复、时间解析失败、非正时长、过短/超长时长、站点缺失、坐标缺失及越界。
2. 将最短和最长时长阈值、边界是否包含写入配置及报告。明确非法记录与“需进一步核查的可疑记录”的区别。
3. 按 `started_at` 筛选 2024 年 1 月订单。合法跨月还车记录使用完整结束时间计算时长。
4. 站点 ID 按字符串读取，以 ID 作为站点标识。为同 ID 多名称建立可追溯的名称映射；不要仅因名称相同而合并不同 ID。
5. 同一记录有多个异常时保留多项审查标记；清洗漏斗按固定顺序记录本步新增删除数。
6. 与 B、C 冻结字段名称、文件名称、时间语义和子集用途，写入 `docs/data-dictionary.md`。

**完成标准：**每条清洗规则都有理由和可计数的影响，漏斗各步数量可以核对。

**行数复核：**分工方案给出的全量有效集为 **233,180 行**、站点有效集为 **180,914 行**，用作参考核对值。附件开头与部分表格存在裁切，未完整提供全部阈值。若实际结果不同，输出差异与原因并核对规则，不直接按目标行数截取数据。

### 第 4 步：完成清洗、特征生成与双子集导出（10 月 25 日上午）

**建议按函数拆分**

`load_raw_data()` → `audit_data()` → `clean_data()` → `add_features()` → `export_datasets()`。

`src/data_cleaning.py` 作为可直接运行的入口，另提供可导入函数给 Notebook 使用。

**建议的统一字段约定**

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| 原始 13 列 | 保留原字段名 | 时间列解析为 datetime，ID 保持字符串，坐标转数值 |
| `duration_min` | float | `(ended_at - started_at)` 的总分钟数 |
| `dist_km` | float，可缺失 | 使用有效起终点经纬度和 Haversine 公式计算的直线距离，单位 km |
| `hour` | int | 出发小时，0–23 |
| `weekday` | int | 出发日期星期序号，周一为 0、周日为 6 |
| `is_weekend` | bool | `weekday >= 5`；不等同于节假日标记 |
| `has_station_info` | bool | 起终点站点 ID 均非空，名称映射检查另行记录 |
| `is_dockless_ebike` | bool | 建议定义为电单车且至少一端站点 ID 缺失，作为操作性代理标记 |
| `is_loop_trip` | bool，可缺失 | 两端 ID 已知时比较是否相同；站点不足时记为未知 |

`dist_km` 是直线距离，不能称为实际骑行路程。缺失坐标不补成 0；距离不可计算的记录应标明。站点缺失也可能源自记录问题，`is_dockless_ebike` 的代理口径需在报告中说明。

**双子集建议**

| 本地输出 | 用途 | 筛选原则 |
| --- | --- | --- |
| `data/processed/clean_trips.csv` | B 的全城时间分析，以及马文博的基础探索 | 满足冻结的基础有效性规则；站点缺失本身不直接作为全量删除条件 |
| `data/processed/station_trips.csv` | C 的站点、OD、潮汐分析，以及 B 的站点需求分析 | 从全量有效集筛出起终点站点 ID 均有效的记录 |

空间图表另筛选有效坐标；马文博的距离分布也使用距离非空的子样本并标注样本量。CSV 重新读入时，B、C 需按字典指定 ID、时间、布尔类型，特别避免将字符串 `"False"` 直接强转为 bool。

**完成标准：**

- [ ] 从项目根目录运行 `python -m src.data_cleaning` 成功。
- [ ] 输出两份 CSV、质量审查结果和各步计数。
- [ ] 站点子集是全量有效集的子集，两份数据的 `ride_id` 唯一。
- [ ] 站点子集 ID 完整；所有距离非负且有限，缺失情况单独统计。
- [ ] 相同输入和配置重复运行，行数与关键统计一致。
- [ ] B、C 根据说明各自在本地生成数据，并确认字段可用。

### 第 5 步：完成图 1–3 与基础探索（10 月 25 日下午）
